МОДУЛЬ 00

Как учиться по этому курсу

Метод важнее материала: один и тот же текст одному даёт навык, а другому только ощущение, что он «всё понял».

C не учится чтением. Он учится руками: ты пишешь код, компилятор ругается, ты разбираешься почему. Поэтому каждый модуль устроен одинаково: короткая теория, пример, ловушки и упражнения. Упражнения обязательны, без них модуль не засчитывается.

Пять правил

  1. Перепечатывай примеры руками, не копируй. Кнопка «Копировать» нужна для потом, когда ты уже понял код. Руки запоминают синтаксис быстрее глаз.
  2. Ломай примеры нарочно. Убери ;, поменяй тип, выйди за границу массива. Прочитай, что сказал компилятор. Ошибки компилятора станут понятными только так.
  3. Предсказывай вывод до запуска. Перед каждым запуском скажи вслух, что программа напечатает. Если ошибся, найди, где именно твоя модель разошлась с реальностью.
  4. Код каждый день. 40 минут ежедневно дают больше, чем 5 часов в выходной.
  5. Пропорция 20/80. Видео и чтение занимают 20% времени, а 80% уходит на написание кода. Видео дают картину, навык дают задачи.
Прогресс сохраняется

Внизу каждого модуля есть отметка «Модуль пройден». Ставь её, только когда сделал все упражнения уровня «база». Отметки хранятся в этом браузере, а шкала прогресса в оглавлении слева.

Уровни упражнений: база делать обязательно, средне очень желательно, сложно для тех, кто хочет глубже.

МОДУЛЬ 01

Окружение: VS Code и компилятор

Ответ на вопрос «почему не просто VS Code» и рабочая настройка для Windows, macOS и Linux.

VS Code использовать можно и нужно

Путаница возникает из-за того, что VS Code — это редактор, а не компилятор. Это очень удобный блокнот с подсветкой, подсказками и отладчиком. Превращать файл .c в работающую программу он сам не умеет. Для этого нужен компилятор (gcc или clang), а он живёт в операционной системе.

Поэтому правильный вопрос звучит так: «где взять компилятор и инструменты к нему». Связка такая: VS Code для написания кода, gcc для сборки, терминал для запуска.

Почему я советую Linux-окружение (на Windows через WSL)

  • Инструменты. Отладчик gdb и проверка памяти valgrind работают в Linux. Санитайзеры (AddressSanitizer) под Windows с MinGW поддерживаются плохо. Именно эти инструменты ловят 90% ошибок новичка в C.
  • Профессия. Embedded, ядро Linux, драйверы и серверный софт строятся на Linux-инструментах. Привыкать к терминалу лучше с первого дня.
  • Материалы. Почти все курсы, книги и задачники по C рассчитаны на gcc и Linux.

WSL (Windows Subsystem for Linux) — это настоящая Ubuntu внутри Windows без виртуальной машины и двойной загрузки. VS Code умеет работать с ней напрямую: окно открывается в Windows, а компиляция идёт в Linux.

Установка: Windows (рекомендуемый путь)

1. Открой PowerShell от имени администратора и выполни команду ниже, затем перезагрузи компьютер. После перезагрузки откроется Ubuntu и попросит придумать имя пользователя и пароль.

wsl --install

2. В терминале Ubuntu установи компилятор и инструменты:

sudo apt update
sudo apt install build-essential gdb valgrind
gcc --version        # проверка: должна напечататься версия

3. Установи VS Code для Windows (не внутрь Ubuntu). В разделе расширений (Ctrl+Shift+X) поставь WSL и C/C++ от Microsoft.

4. Создай папку курса и открой её в VS Code прямо из Ubuntu:

mkdir -p ~/c-course && cd ~/c-course
code .               # VS Code откроется в режиме «WSL: Ubuntu»

Внизу слева в VS Code появится зелёная плашка WSL: Ubuntu. Если расширение C/C++ предложит «Install in WSL», соглашайся.

Без WSL

Можно поставить MSYS2 и в нём выполнить pacman -S mingw-w64-ucrt-x86_64-gcc. Компилировать это позволит, но valgrind не будет, а санитайзеры будут работать с ограничениями. Для учёбы WSL удобнее.

Установка: macOS

xcode-select --install   # ставит clang, make, lldb
clang --version

На Mac команда gcc на самом деле запускает clang, и для курса это нормально. Все флаги ниже работают. Valgrind на Apple Silicon не работает, его роль выполняют санитайзеры и утилита leaks. Отладчик здесь lldb, его команды почти совпадают с gdb.

Установка: Linux

sudo apt install build-essential gdb valgrind

Как собирать: команда, которую ты будешь писать тысячу раз

gcc -std=c17 -Wall -Wextra -Wpedantic -g -fsanitize=address,undefined main.c -o main
./main
ФлагЧто делает
-std=c17Стандарт языка C17: современный и поддерживается везде
-Wall -Wextra -WpedanticВключают предупреждения. Предупреждение в C почти всегда означает настоящую ошибку
-gДобавляет отладочную информацию: номера строк в ошибках и работа отладчика
-fsanitize=address,undefinedСанитайзеры ловят выход за границы, утечки и неопределённое поведение прямо во время работы
-o mainИмя готовой программы (по умолчанию было бы a.out)

Чтобы не набирать это каждый раз, добавь сокращение в конец файла ~/.bashrc и перезапусти терминал:

alias cc17='gcc -std=c17 -Wall -Wextra -Wpedantic -g -fsanitize=address,undefined'
# использование: cc17 main.c -o main && ./main
Совет на первые недели

Не жми кнопку «Run» в VS Code и не ставь расширение Code Runner. Собирай из терминала руками (Ctrl+` открывает терминал внутри VS Code). Так ты поймёшь, что происходит, и не растеряешься, когда кнопки не будет: на сервере, в микроконтроллере, на собеседовании.

Ничего не установилось, а хочется начать прямо сейчас? Первый день можно провести в браузере: onlinegdb.com (выбери язык C) или godbolt.org. Но установку не откладывай.

Упражнения

  1. базаУстанови окружение для своей ОС. Убедись, что gcc --version печатает версию.
  2. базаДобавь алиас cc17 и проверь, что он работает.
  3. среднеВыучи 10 команд терминала: pwd, ls -la, cd, mkdir, rm, cp, mv, cat, less, man. Например, man printf открывает справку прямо в терминале.
МОДУЛЬ 02

Первая программа и путь от текста к программе

Компиляция состоит из четырёх этапов. Знать их нужно, чтобы понимать ошибки вроде «undefined reference».

#include <stdio.h>   // подключаем объявления функций ввода-вывода (printf)

int main(void) {      // точка входа: отсюда начинается выполнение
    printf("Привет, C!\n");   // \n означает перевод строки
    return 0;         // 0 сообщает системе, что всё прошло успешно
}
вывод
Привет, C!
cc17 hello.c -o hello
./hello
echo $?      # покажет код возврата программы: 0

Что происходит при сборке

Команда gcc на самом деле запускает четыре программы подряд. Каждый этап можно выполнить отдельно и посмотреть на результат:

ЭтапКомандаЧто получается
1. Препроцессорgcc -E hello.c -o hello.iТекст, в который вставлено содержимое stdio.h. Открой файл и посмотри, сколько там строк
2. Компиляцияgcc -S hello.c -o hello.sАссемблер: команды процессора в текстовом виде
3. Ассемблированиеgcc -c hello.c -o hello.oОбъектный файл: машинный код, но ещё без библиотек
4. Линковкаgcc hello.o -o helloГотовая программа: линкер подключил код printf из стандартной библиотеки

Это объясняет два вида ошибок. Если компилятор пишет error: expected ';', проблема на этапе компиляции, в синтаксисе. Если линкер пишет undefined reference to 'foo', функция объявлена, но её код не найден: ты забыл файл .c или библиотеку.

Анатомия программы

  • #include — команда препроцессору: «вставь сюда содержимое файла». В заголовочных файлах (.h) лежат объявления функций.
  • int main(void) — главная функция. Слово int означает, что она возвращает целое число, void — что аргументов нет.
  • Фигурные скобки { } задают блок кода. Каждая инструкция заканчивается точкой с запятой ;.
  • Комментарии бывают двух видов: // до конца строки и /* многострочный */.

Упражнения

  1. базаНапиши программу, которая печатает твоё имя, возраст и город, каждое на новой строке.
  2. базаУбери #include, потом ;, потом закрывающую }. Для каждого случая прочитай сообщение компилятора целиком.
  3. среднеПройди все четыре этапа вручную. Сравни число строк в hello.c и hello.i командой wc -l.
  4. среднеСделай return 3; и проверь echo $?. Подумай, зачем программе код возврата.
МОДУЛЬ 03

Переменные, типы и printf

В C у каждой переменной есть тип, и тип определяет, сколько байт она занимает и как эти байты читать.

Переменная — это именованный кусок памяти. Тип говорит компилятору две вещи: сколько байт выделить и как интерпретировать эти байты. Один и тот же байт 01000001 — это число 65, если тип целый, и буква 'A', если ты печатаешь его как символ.

#include <stdio.h>
#include <stdint.h>    // типы точного размера: uint8_t, int32_t...
#include <stdbool.h>   // bool, true, false

int main(void) {
    int age = 25;
    double price = 19.99;
    char letter = 'C';
    bool ready = true;
    uint8_t byte = 200;            // ровно 8 бит, без знака: 0..255
    int64_t big = 9000000000LL;    // не влезает в 32 бита

    printf("age=%d price=%.2f\n", age, price);
    printf("letter=%c code=%d\n", letter, letter);   // символ и его код
    printf("ready=%d byte=%d\n", ready, byte);
    printf("big=%lld\n", (long long)big);
    printf("sizeof: int=%zu double=%zu char=%zu\n",
           sizeof(int), sizeof(double), sizeof(char));
    return 0;
}
вывод (на x86-64 и ARM64)
age=25 price=19.99
letter=C code=67
ready=1 byte=200
big=9000000000
sizeof: int=4 double=8 char=1

Спецификаторы printf

Строка формата в printf содержит «дырки», которые заполняются аргументами по порядку. Спецификатор обязан соответствовать типу, иначе программа напечатает мусор. Флаг -Wall такие ошибки ловит.

СпецификаторТипПример

%uunsigned intprintf("%u", 42u)
%ld / %lldlong / long longprintf("%lld", 1LL)
%zusize_tprintf("%zu", sizeof(int))
%f, %.2fdoubleprintf("%.2f", 3.14159) → 3.14
%cсимволprintf("%c", 'A')
%sстрокаprintf("%s", "hi")

Ввод: scanf

int n;
printf("Введи число: ");
if (scanf("%d", &n) != 1) {      // scanf возвращает число успешно прочитанных значений
    printf("Это не число\n");
    return 1;
}
printf("Квадрат: %d\n", n * n);

Знак & перед n означает «адрес переменной». Функции scanf нужно знать, куда записать число. Подробно это разберём в модуле про указатели, а пока просто запомни: в scanf перед обычной переменной ставится &.

Константы

const double PI = 3.14159;    // изменить нельзя, компилятор не даст
#define MAX_USERS 100         // текстовая замена препроцессором, без типа
Ловушка: переполнение

У беззнаковых типов переполнение определено: uint8_t x = 255; x++; даёт 0, число «заворачивается». А переполнение знакового int — это неопределённое поведение (UB). Компилятор вправе считать, что его не бывает, и выбросить твои проверки. Подробности в модуле 17.

Ловушка: неинициализированные переменные

int x; printf("%d", x); напечатает мусор, то есть то, что лежало в этой памяти раньше. Всегда задавай начальное значение.

Упражнения

  1. базаПрограмма спрашивает температуру в Цельсиях и печатает её в Фаренгейтах (F = C × 9 / 5 + 32) с одним знаком после запятой.
  2. базаНапечатай sizeof всех типов из таблицы. Сравни свои результаты с таблицей.
  3. среднеНапечатай символы с кодами от 32 до 126 в виде таблицы «код → символ». Это таблица ASCII.
  4. среднеСделай uint8_t x = 250; и в цикле прибавляй 1 десять раз, печатая значение. Объясни результат.
  5. сложноПодключи <limits.h> и <stdint.h> и напечатай INT_MAX, INT_MIN, UINT32_MAX, INT64_MAX. Объясни, почему INT_MIN по модулю на единицу больше INT_MAX.

Операторы и выражения

Целочисленное деление, приведение типов и разница между = и == ломают больше программ новичков, чем что-либо ещё.

#include <stdio.h>

int main(void) {
    int a = 7, b = 2;
    printf("%d %d\n", a / b, a % b);   // 3 1: целые делятся нацело, % даёт остаток
    printf("%.1f\n", a / 2.0);         // 3.5: если один операнд дробный, деление дробное
    printf("%.1f\n", (double)a / b);   // 3.5: явное приведение типа

    int x = 5;
    int y = x++;    // сначала y = 5, потом x станет 6
    int z = ++x;    // сначала x станет 7, потом z = 7
    printf("%d %d %d\n", x, y, z);

    int max = (a > b) ? a : b;         // тернарный оператор: условие ? если да : если нет
    printf("max=%d\n", max);

    printf("%d %d\n", 3 > 2, 3 == 4);  // сравнение даёт 1 (истина) или 0 (ложь)
    return 0;
}
вывод
3 1
3.5
3.5
7 5 7
max=7
1 0

В C нет отдельного логического типа в старом смысле: ноль — ложь, всё остальное — истина. Поэтому if (n) означает «если n не ноль».

Ловушка: = вместо ==

if (x = 5) не сравнивает, а присваивает 5 в x. Результат 5 считается истиной, и условие выполняется всегда. Флаг -Wall предупредит, поэтому никогда не игнорируй предупреждения.

Ловушка: i = i++

Выражения вида i = i++ или a[i] = i++ — это неопределённое поведение: переменная меняется дважды без чёткого порядка. Пиши по одному изменению на строку.

Приоритеты запоминать не нужно. Если сомневаешься, ставь скобки: (a & mask) == 0. Без скобок здесь будет ошибка, потому что == выполняется раньше &.

Упражнения

  1. базаВведи количество секунд и выведи его в формате ЧЧ:ММ:СС (подсказка: /, % и %02d).
  2. базаВведи трёхзначное число и выведи его цифры в обратном порядке.
  3. среднеПроверь, является ли год високосным, одним выражением с && и || (делится на 4 и не делится на 100, либо делится на 400).
  4. среднеНапечатай -7 / 2 и -7 % 2. Узнай, в какую сторону C округляет деление отрицательных чисел.
МОДУЛЬ 05

Ветвления и циклы

С if, for и while можно написать любой алгоритм. Остальное в языке — удобства.

#include <stdio.h>

int main(void) {
    // for: когда известно, сколько раз повторять
    for (int i = 1; i <= 15; i++) {
        if (i % 15 == 0)      printf("FizzBuzz ");
        else if (i % 3 == 0)  printf("Fizz ");
        else if (i % 5 == 0)  printf("Buzz ");
        else                  printf("%d ", i);
    }
    printf("\n");

    // while: когда повторяем, пока выполняется условие
    int n = 12345, sum = 0;
    while (n > 0) {
        sum += n % 10;   // берём последнюю цифру
        n /= 10;         // отрезаем её
    }
    printf("сумма цифр = %d\n", sum);

    // switch: выбор по целому значению
    int day = 3;
    switch (day) {
        case 1:  printf("понедельник\n"); break;
        case 2:  printf("вторник\n");     break;
        case 3:  printf("среда\n");       break;   // без break выполнение «провалится» дальше
        default: printf("другой день\n");

        if (i > 7) break;           // выйти из цикла
        printf("%d ", i);
    }
    printf("\n");
    return 0;
}

Цикл do-while

Тело выполнится хотя бы один раз, а условие проверяется в конце. Это удобно для ввода с повтором:

Функции

Функции режут программу на понятные куски. Главное, что нужно о них знать в C: аргументы всегда передаются копией.

#include <stdio.h>

// Прототипы говорят компилятору: «такие функции есть, их код будет ниже»
int square(int x);
unsigned long long factorial(unsigned n);
void try_change(int x);
void counter(void);

int main(void) {
    printf("%d\n", square(7));
    printf("%llu\n", factorial(10));

    int v = 1;
    try_change(v);
    printf("v = %d\n", v);      // по-прежнему 1: функция меняла копию

    counter();
    counter();
    counter();
    return 0;
}

int square(int x) {
    return x * x;
}

unsigned long long factorial(unsigned n) {
    if (n <= 1) return 1;          // база рекурсии: без неё стек переполнится
    return n * factorial(n - 1);
}

void try_change(int x) {
    x = 100;                       // меняется только локальная копия
    printf("внутри функции x = %d\n", x);
}

void counter(void) {
    static int calls = 0;          // static: переменная живёт между вызовами
    calls++;
    printf("вызов №%d\n", calls);
}

Что нужно запомнить

  • Передача по значению. Функция получает копию аргумента. Чтобы функция изменила переменную снаружи, ей передают адрес переменной (модуль 08).
  • Прототип — объявление без тела. Без него компилятор не знает, что функция существует, если она определена ниже места вызова. В больших программах прототипы живут в .h-файлах.
  • void в возвращаемом типе означает «ничего не возвращает», а в скобках (void) — «аргументов нет». Пустые скобки () в старых стандартах означают «аргументы неизвестны», поэтому пиши void явно.
  • Область видимости. Переменная живёт внутри блока { }, где объявлена. Локальные переменные создаются при входе в функцию и исчезают при выходе.
  • Рекурсия работает, но каждый вызов занимает место на стеке (обычно его всего 1–8 МБ). В embedded стек бывает размером в килобайты, там глубокой рекурсии избегают.

Если функция объявлена как int, но до return выполнение не дошло, результат не определён. -Wall предупредит: control reaches end of non-void function.

Массивы

Массив — это несколько переменных одного типа подряд в памяти. C не проверяет, что ты остался в его границах.

#include <stdio.h>

#define N 5

// Массив в функцию передаётся как адрес первого элемента,
// поэтому длину надо передавать отдельно
int sum(const int *arr, size_t len) {
    int s = 0;
    for (size_t i = 0; i < len; i++)
        s += arr[i];
    return s;
}

int main(void) {
    int nums[N] = {3, 1, 4, 1, 5};
    int zeros[10] = {0};                              // все элементы равны 0
    size_t len = sizeof nums / sizeof nums[0];        // длина массива: 20 / 4 = 5

    printf("len=%zu sum=%d\n", len, sum(nums, len));
    printf("zeros[9]=%d\n", zeros[9]);

    int grid[2][3] = { {1, 2, 3}, {4, 5, 6} };       // двумерный массив
    for (int r = 0; r < 2; r++) {
        for (int c = 0; c < 3; c++)
            printf("%d ", grid[r][c]);
        printf("\n");
    }
    return 0;
}

  • Индексы начинаются с 0. У массива из 5 элементов последний индекс 4.

Указатели и массивы

Запись arr[i] — это буквально *(arr + i): взять адрес начала, сдвинуться на i элементов и прочитать. Поэтому индексы начинаются с нуля: первый элемент лежит на сдвиге 0. И поэтому массив, переданный в функцию, превращается в указатель.

const и указатели

const int *p1 = &x;   // нельзя менять *p1 (данные), можно менять сам p1
int *const p2 = &x;   // нельзя менять p2 (адрес), можно менять *p2
const int *const p3 = &x;   // нельзя ничего

Правило чтения: читай объявление справа налево. int *const p2: «p2 — константный указатель на int». Если запутался, вставь объявление на cdecl.org, и он переведёт его на английский.

Привычка: если функция только читает данные по указателю, пиши const, как в sum(const int *arr, …). Это документация и защита одновременно.

Указатель на указатель

int x = 5;
int *p = &x;
int **pp = &p;     // адрес переменной, в которой лежит адрес
**pp = 6;          // x стал 6

Зачем это нужно: чтобы функция могла изменить сам указатель снаружи, например выделить память и вернуть её через аргумент. Ещё char **argv в main — это массив строк.

Ловушки
  • Неинициализированный указатель (int *p; *p = 5;) указывает в случайное место. Запись туда портит память или роняет программу.
  • Разыменование NULL обычно приводит к Segmentation fault. Проверяй указатели, которые могут быть пустыми.
  • Висячий указатель: адрес локальной переменной, возвращённый из функции. Функция завершилась, её стек освобождён, и указатель смотрит в мусор.
  • В объявлении int* a, b; только a является указателем, а b — обычный int. Поэтому звёздочку пишут у имени: int *a, *b;.

  4. среднеНапиши функцию, которая возвращает адрес локальной переменной, и посмотри предупреждение компилятора. Объясни, почему это ошибка.

Строки

Типа «строка» в C нет. Есть массив символов, который заканчивается нулевым байтом, и твоя ответственность за его длину.

#include <stdio.h>
#include <string.h>

size_t my_strlen(const char *s) {
    const char *p = s;
    while (*p != '\0')        // идём до нулевого байта
        p++;
    return (size_t)(p - s);   // разница адресов равна длине
}

int main(void) {
    char word[] = "Hello";          // 6 байт: H e l l o \0
    const char *lit = "World";      // строковый литерал: менять его нельзя
    printf("%zu %zu %zu\n", sizeof word, strlen(word), my_strlen(lit));

    char buf[32];
    snprintf(buf, sizeof buf, "%s, %s!", word, lit);   // безопасная склейка с лимитом
    printf("%s\n", buf);

    if (strcmp(word, "Hello") == 0)   // строки сравнивают через strcmp, а не ==
        printf("равны\n");

    for (size_t i = 0; word[i] != '\0'; i++)
        printf("[%c:%d]", word[i], word[i]);
    printf("\n");

    printf("%zu\n", strlen("Привет"));  // 12: кириллица в UTF-8 занимает 2 байта на букву
    return 0;
}

Ниже динамический массив, который растёт сам. Похожие структуры лежат внутри std::vector в C++ и list в Python. Разбери каждую строку:

#include <stdio.h>
#include <stdlib.h>

typedef struct {
    int *data;     // указатель на блок в куче
    size_t len;    // сколько элементов сейчас
    size_t cap;    // на сколько элементов выделено места
} Vec;

int vec_push(Vec *v, int x) {
    if (v->len == v->cap) {
        size_t new_cap = v->cap ? v->cap * 2 : 4;              // удваиваем ёмкость
        int *p = realloc(v->data, new_cap * sizeof *p);
        if (p == NULL) return -1;     // памяти нет: старый блок цел, сообщаем об ошибке
        v->data = p;
        v->cap = new_cap;
    }
    v->data[v->len++] = x;
    return 0;
}

void vec_free(Vec *v) {
    free(v->data);
    v->data = NULL;               // защита от повторного использования
    v->len = v->cap = 0;
}

int main(void) {
    Vec v = {0};                  // все поля равны нулю, data == NULL
    for (int i = 0; i < 10; i++) {
        if (vec_push(&v, i * i) != 0) {
            vec_free(&v);
            return 1;
        }
    }
    for (size_t i = 0; i < v.len; i++)
        printf("%d ", v.data[i]);
    printf("\nlen=%zu cap=%zu\n", v.len, v.cap);
    vec_free(&v);                 // выделил — освободи
    return 0;
}
вывод

len=10 cap=16

Разбор некоторых деталей:

  • v->len — это сокращение для (*v).len: поле структуры, к которой обращаемся через указатель.
  • new_cap * sizeof *p — размер считается от типа указателя, а не через sizeof(int). Поменяешь тип, и формула останется верной.
  • realloc(NULL, n) работает как malloc(n), поэтому первый вызов с пустым data тоже корректен.
  • Результат realloc сначала кладём во временную переменную p. Если написать v->data = realloc(v->data, …) и получить NULL, адрес старого блока потеряется, и будет утечка.
Пять смертных грехов
  • Утечка: забыл free. Программа медленно съедает память.
  • Use-after-free: использовал память после free. Одна из самых опасных уязвимостей.
  • Double free: вызвал free дважды для одного адреса. Ломает внутренние структуры кучи.
  • Не проверил NULL после malloc.
  • Неверный размер: malloc(n) вместо malloc(n * sizeof(int)).

Все пять ловят ASan и valgrind. Запускай их всегда.

Правило владения

У каждого блока памяти должен быть один понятный владелец: кто вызвал malloc, тот (или явно указанный код) вызывает free. Пиши функции парами: vec_init / vec_free, list_create / list_destroy.

  2. базаНапиши char *my_strdup(const char *s), которая возвращает копию строки в куче.

Структуры, enum и union

Структуры собирают разнородные данные в одну сущность. Из них сделаны пакеты сетевых протоколов, регистры железа и файлы.

#include <stdio.h>
#include <string.h>
#include <stdint.h>

typedef enum { ROLE_USER, ROLE_ADMIN } Role;   // именованные целые константы: 0, 1

typedef struct {
    char name[32];
    int age;
    Role role;
} User;

typedef struct {
    char a;    // 1 байт
    int b;     // 4 байта, но должен начинаться с адреса, кратного 4
    char c;    // 1 байт
} Padded;      // sizeof обычно 12, а не 6: компилятор вставляет выравнивание

void birthday(User *u) {
    u->age++;                    // то же, что (*u).age++
}

int main(void) {
    User u = { .name = "Ann", .age = 30, .role = ROLE_ADMIN };   // именованная инициализация
    birthday(&u);
    printf("%s, %d, %s\n", u.name, u.age, u.role == ROLE_ADMIN ? "admin" : "user");

    User copy = u;               // структуры копируются целиком, вместе с массивом внутри
    strcpy(copy.name, "Bob");    // здесь безопасно: "Bob" точно влезает в 32 байта
    printf("%s / %s\n", u.name, copy.name);

    printf("sizeof(Padded) = %zu\n", sizeof(Padded));

    // union: все поля лежат в одной и той же памяти
    union {
        uint32_t word;
        uint8_t bytes[4];
    } v = { .word = 0x11223344 };
    printf("первый байт: 0x%02x\n", v.bytes[0]);   // 0x44 на x86 и ARM (little-endian)
    return 0;
}

Что нужно запомнить

  • typedef даёт типу короткое имя: User вместо struct User.
  • Доступ к полям: через точку у переменной (u.age) и через стрелку у указателя (p->age).
  • Большие структуры передавай по указателю (const User *u), иначе каждый вызов копирует их целиком.
  • Выравнивание (padding). Процессор быстрее читает данные с «ровных» адресов, поэтому компилятор вставляет пустые байты между полями. Если упорядочить поля от больших к маленьким, структура станет меньше. В embedded и сетевых протоколах это важно.
  • Порядок байтов (endianness). x86 и ARM хранят младший байт первым (little-endian), а в сетевых протоколах принят обратный порядок. Пример с union выше показывает это наглядно.
Зачем union

Так экономят память там, где в один момент нужно только одно из полей. Ещё union используют для разбора байтов, например пакета или регистра. Помни, что формально чтение не того поля, которое записывали последним, имеет нюансы в стандарте. Для переносимого кода байты достают сдвигами (модуль 14) или через memcpy.

  1. базаСтруктура Point { double x, y; } и функции distance(Point a, Point b) и midpoint.
  2. базаМассив из 5 структур Student { char name[32]; int grade; }. Найди лучшего студента и отсортируй массив по оценке.
  3. среднеПоиграй с порядком полей в Padded и добейся sizeof = 8. Напечатай смещения полей через offsetof из <stddef.h>.
  4. сложноОпиши структурой заголовок файла BMP (первые 14 байт). Прочитай настоящий .bmp и напечатай размер файла. Учти, что из-за выравнивания структура может не совпасть с файлом, и найди, как это решается.

Несколько файлов и make

Реальные проекты состоят из десятков файлов. Нужно понимать, как они связываются и как собирать их одной командой.

Принцип такой: объявления (что есть) кладут в .h, определения (как работает) — в .c. Каждый .c компилируется отдельно в .o, потом линкер их склеивает. Возьмём наш Vec и разложим его по файлам. Структура проекта:

vec/
├── vec.h       # интерфейс: тип и прототипы
├── vec.c       # реализация
├── main.c      # использование
└── Makefile    # правила сборки
#ifndef VEC_H          // include guard: защита от двойного включения
#define VEC_H

#include <stddef.h>    // size_t

typedef struct {
    int *data;
    size_t len;
    size_t cap;
} Vec;

int  vec_push(Vec *v, int x);
void vec_free(Vec *v);

#endif
#include "vec.h"       // свои заголовки в кавычках, системные в угловых скобках
#include <stdlib.h>

// static на уровне файла: функция видна только внутри vec.c
static size_t grow(size_t cap) {
    return cap ? cap * 2 : 4;
}

int vec_push(Vec *v, int x) {
    if (v->len == v->cap) {
        size_t new_cap = grow(v->cap);
        int *p = realloc(v->data, new_cap * sizeof *p);
        if (p == NULL) return -1;
        v->data = p;
        v->cap = new_cap;
    }
    v->data[v->len++] = x;
    return 0;
}

void vec_free(Vec *v) {
    free(v->data);
    v->data = NULL;
    v->len = v->cap = 0;
}
#include <stdio.h>
#include "vec.h"

int main(void) {
    Vec v = {0};
    for (int i = 1; i <= 5; i++)
        if (vec_push(&v, i * 10) != 0) return 1;

    for (size_t i = 0; i < v.len; i++)
        printf("%d ", v.data[i]);
    printf("\n");
    vec_free(&v);
    return 0;
}

Собрать можно одной командой: gcc main.c vec.c -o app. Но когда файлов 30, пересобирать все при каждом изменении долго. Для этого есть make: он пересобирает только то, что изменилось.

Ловушка: табуляция в Makefile

Строки с командами (под app:, %.o:, clean:) должны начинаться с символа табуляции, а не с пробелов. Иначе make напишет missing separator. Кнопка «Копировать» сохраняет табуляцию.

Как читать правило: app: main.o vec.o значит «чтобы получить app, нужны main.o и vec.o, а строка ниже говорит, как их склеить». $< — первый файл из зависимостей, $@ — цель. Команда make clean удаляет результаты сборки.

Файлы, аргументы и обработка ошибок

Программа становится полезной, когда читает файлы, принимает аргументы и честно сообщает об ошибках.

Ниже своя версия утилиты wc: считает строки, слова и байты в файле.

#include <stdio.h>
#include <ctype.h>

int main(int argc, char *argv[]) {        // argc: число аргументов, argv: массив строк
    if (argc != 2) {
        fprintf(stderr, "Использование: %s файл\n", argv[0]);
        return 1;                          // ненулевой код означает ошибку
    }

    FILE *f = fopen(argv[1], "r");
    if (f == NULL) {
        perror(argv[1]);                   // напечатает причину, например No such file or directory
        return 1;
    }

    long lines = 0, words = 0, bytes = 0;
    int in_word = 0;
    int ch;                                // int, а не char: так EOF отличается от байта 0xFF
    while ((ch = fgetc(f)) != EOF) {
        bytes++;
        if (ch == '\n') lines++;
        if (isspace(ch)) {
            in_word = 0;
        } else if (!in_word) {
            in_word = 1;
            words++;
        }
    }
    fclose(f);

    printf("%ld %ld %ld %s\n", lines, words, bytes, argv[1]);
    return 0;
}

#include <stdio.h>
#include <stdint.h>

#define BIT(n) (1u << (n))

void print_bin(uint8_t x) {
    for (int i = 7; i >= 0; i--)
        putchar((x & BIT(i)) ? '1' : '0');
    putchar('\n');
}

int count_ones(uint32_t x) {
    int n = 0;
    while (x) {
        x &= x - 1;     // этот трюк гасит младшую единицу
        n++;
    }
    return n;
}

int main(void) {
    uint8_t reg = 0;
    reg |= BIT(3);              // установить бит 3
    reg |= BIT(0);              // установить бит 0
    print_bin(reg);
    reg &= (uint8_t)~BIT(0);    // сбросить бит 0
    print_bin(reg);
    reg ^= BIT(7);              // переключить бит 7
    print_bin(reg);
    printf("бит 3 %s\n", (reg & BIT(3)) ? "установлен" : "сброшен");

    printf("0x%X = %u\n", 0xFFu, 0xFFu);
    printf("единиц в 0xF0F0: %d\n", count_ones(0xF0F0));

    uint32_t color = 0x3366CCu;                 // цвет в формате RGB
    unsigned r = (color >> 16) & 0xFF;          // достаём байты сдвигом и маской
    unsigned g = (color >> 8) & 0xFF;
    unsigned b = color & 0xFF;
    printf("r=%u g=%u b=%u\n", r, g, b);
    return 0;
}

// Регистр выхода порта GPIO — это просто адрес в памяти (адрес условный)
#define GPIO_OUT (*(volatile uint32_t *)0x40020014u)
#define LED_PIN  5

GPIO_OUT |=  (1u << LED_PIN);    // включить светодиод
GPIO_OUT &= ~(1u << LED_PIN);    // выключить

volatile говорит компилятору: «значение может поменять железо, не оптимизируй чтение и запись». Без него компилятор вправе выкинуть повторяющиеся обращения к регистру.

Ловушки
  • Для битовых операций используй беззнаковые типы. Сдвиг отрицательного числа или сдвиг в знаковый бит может оказаться неопределённым поведением.
  • Сдвиг на число бит, большее или равное ширине типа (1u << 32 для 32-битного), — это UB.
  • Пиши 1u, а не 1. Литерал 1 имеет знаковый тип int.

void* и указатели на функции

Так в C пишут обобщённый код: одна сортировка для любых данных, таблицы обработчиков, колбэки драйверов.

  • void * — «указатель на что угодно». Его можно присвоить в любой указатель на данные и обратно, но разыменовать нельзя: компилятор не знает размер. Так устроены malloc, memcpy и qsort.
  • Указатель на функцию хранит адрес кода. Объявление int (*op)(int, int) читается так: «op — указатель на функцию, которая принимает два int и возвращает int».
#include <stdio.h>
#include <stdlib.h>

// Компаратор для qsort: получает адреса двух элементов как const void*
int cmp_int(const void *a, const void *b) {
    int x = *(const int *)a;
    int y = *(const int *)b;
    return (x > y) - (x < y);   // -1, 0 или 1, без риска переполнения, как у x - y
}

int add(int a, int b) { return a + b; }
int mul(int a, int b) { return a * b; }

int apply(int (*op)(int, int), int a, int b) {
    return op(a, b);            // вызываем функцию, адрес которой нам передали
}

int main(void) {
    int nums[] = {42, 7, 19, 3, 25};
    size_t n = sizeof nums / sizeof nums[0];

    qsort(nums, n, sizeof nums[0], cmp_int);   // одна сортировка для любых типов
    for (size_t i = 0; i < n; i++)
        printf("%d ", nums[i]);
    printf("\n");

    printf("%d %d\n", apply(add, 6, 7), apply(mul, 6, 7));

    int (*ops[])(int, int) = { add, mul };   // таблица функций
    printf("%d\n", ops[1](3, 4));
    return 0;
}
вывод
3 7 19 25 42
13 42
12

Где это встречается в реальности: таблица векторов прерываний в микроконтроллере (массив адресов обработчиков), структура file_operations в драйверах Linux (указатели на функции open, read, write), колбэки в библиотеках и конечные автоматы.

Сложные типы удобно называть через typedef: typedef int (*BinOp)(int, int);, и дальше писать просто BinOp op.

Упражнения

  1. базаОтсортируй массив строк (const char *words[]) через qsort и strcmp. Подумай, что именно получает компаратор.
  2. среднеКалькулятор: таблица { '+', add }, { '-', sub }, … из структур и поиск функции по символу операции.
  3. сложноНапиши свою void my_sort(void *base, size_t n, size_t size, int (*cmp)(const void *, const void *)) (вставками) и обменивай элементы побайтово.

Неопределённое поведение и отладка

Профессионала на C отличает от любителя умение находить ошибки памяти, а не скорость набора кода.

Что такое UB

Undefined behavior — ситуация, для которой стандарт C не определяет результат. Компилятор вправе считать, что UB в программе никогда не случается, и оптимизировать код исходя из этого. Поэтому программа с UB может работать на твоём ноутбуке, падать на сервере и вести себя иначе с флагом -O2.

Частые случаи UBЧем ловить
Выход за границы массиваASan, valgrind
Use-after-free, double freeASan, valgrind
Чтение неинициализированной переменнойvalgrind, -Wall (частично)
Переполнение знакового целогоUBSan (-fsanitize=undefined)
Разыменование NULLПадение (segfault), отладчик
Сдвиг на ширину типа и большеUBSan
Изменение строкового литералаПадение, -Wwrite-strings

Санитайзеры на практике

#include <stdlib.h>

int main(void) {
    int *arr = malloc(5 * sizeof *arr);
    if (arr == NULL) return 1;
    for (int i = 0; i <= 5; i++)   // ошибка: <= вместо <
        arr[i] = i;
    free(arr);
    return 0;
}

    #0 0x55ab49d15344 in main bug.c:7

0x503000000054 is located 0 bytes after 20-byte region [0x503000000040,0x503000000054)

Как читать отчёт: что случилось (heap-buffer-overflow, то есть выход за границу блока в куче), где (bug.c:7, запись 4 байт), чья это память (блок в 20 байт, выделенный в строке 4). Мы записали сразу за его концом. Ошибка найдена за секунду, а без санитайзера программа, скорее всего, отработала бы «нормально».

valgrind

gcc -g bug.c -o bug             # без -fsanitize: valgrind и ASan вместе не работают
valgrind --leak-check=full ./bug

Valgrind медленнее ASan, но не требует пересборки с особыми флагами и хорошо находит утечки и чтение неинициализированной памяти.

В VS Code тот же gdb работает через графический интерфейс: поставь точку останова кликом слева от номера строки и нажми F5. Расширение C/C++ предложит создать конфигурацию запуска. Но команды выше всё равно выучи: на удалённом сервере или плате графического интерфейса не будет.

Дополнительные проверки

  • -Werror превращает предупреждения в ошибки и не даёт их игнорировать.
  • -Wconversion -Wshadow включают предупреждения о неявных преобразованиях типов и затенённых переменных. Включай их, когда базовые флаги перестанут ругаться.
  • Статические анализаторы (cppcheck, clang-tidy) ищут ошибки без запуска программы.

Упражнения

  1. базаЗапусти bug.c с ASan и под valgrind. Сравни отчёты.
  2. базаНапиши программу, которая падает с segfault, найди место падения в gdb командой bt.
  3. среднеПройди всю программу vec_demo.c в gdb пошагово и следи за v.cap и v.data во время realloc.
  4. сложноНапиши int x = INT_MAX; if (x + 1 < x) puts("overflow");. Сравни вывод с -O0 и с -O2, потом посмотри ассемблер на godbolt. Это наглядная демонстрация UB.

Финальные проекты

Проекты превращают знание синтаксиса в умение программировать. Эти же проекты станут первыми строками в твоём GitHub.

Сделай минимум три проекта из списка, по порядку сложности. Каждый проект — отдельный репозиторий на GitHub с Makefile и README.md (что делает, как собрать, пример запуска).

  1. базаКалькулятор в обратной польской записи. Ввод 3 4 + 2 * → 14. Стек на массиве, разбор строки, обработка ошибок («мало операндов», «деление на ноль»).
  2. базаmygrep с флагами. -n (номера строк), -i (без учёта регистра), -c (только количество), несколько файлов в аргументах.
  3. среднеБиблиотека связного списка. push_front, push_back, find, remove, reverse, destroy. Плюс тесты на assert и ноль утечек под valgrind.
  4. среднеЧастотный словарь. Хеш-таблица «строка → число» с цепочками. Прочитай большую книгу в .txt и выведи 20 самых частых слов.
  5. среднеИгра «Жизнь» Конвея в терминале: двумерный массив, загрузка начального поля из файла, анимация через перерисовку экрана.
  6. сложноПул-аллокатор. pool_alloc и pool_free для блоков фиксированного размера внутри статического массива на 64 КБ, без вызова malloc. Так управляют памятью в embedded.
Проект считается готовым, когда
  • компилируется с -Wall -Wextra -Wpedantic без единого предупреждения;
  • под ASan и valgrind нет ошибок и утечек;
  • все ошибки ввода обработаны: пустой файл, неверные аргументы, нехватка памяти;
  • человек со стороны может собрать проект по README за минуту.

После этого курса база закрыта, и пора выбирать направление (embedded, системное программирование под Linux или безопасность). Вернись ко мне, когда закончишь проекты, и обсудим следующий шаг.
